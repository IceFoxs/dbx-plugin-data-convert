## SQL 分析页：全流程复验 + 界面收尾

### 引擎（`ui/js/sqlrun.js`）
- **`HAVING` 里用 SELECT 别名 / 聚合**：原本 `havingFn` 走 `predicateGroup → groupExpr`，`resolve()` 只认表列，`HAVING n > 1` 直接报「没有这一列 n」。
  - 做法：`substituteAliases()` 把命中输出列名的 `col` 节点换成 `{ k:'val', fn }`；`groupExpr` 增加 `case 'val'` 直接调 `node.fn`。
  - **坑一**：克隆节点会让 `aggSlot.get()` 取不到（累加器槽位按节点身份登记），`HAVING SUM(b) > 4` 恒为假 → 聚合调用整个原样返回，其余节点「没变就不克隆」。
  - **坑二**：`aliasValueNode` 一开始按 `isAggQuery` 走 `rowExpr`，而 HAVING 只在分组路径求值 → 一律用 `groupExpr`。
- 测试 151 → **203**：`DISTINCT` 组 + `HAVING` 三种写法 + **27 个关键字 / 18 个函数覆盖表**（`KEYWORD_CASES` / `FUNCTION_CASES`，加关键字就往表里加一行）。

### 交互（`ui/js/app/19-datasql.js`）
- **点「运行」= 跑整段**：原来没选区只跑光标那条，用户的批量语句被悄悄跳过。`dataSqlRun` 现在是「入参 sql → 选区 → `opts.statement`（右键『执行当前语句』）→ 整段」，批量才跑得起来。
- **页签只切 class**：`dataSqlSelectBatch` 原本调 `dataSqlRenderBatchTabs()` 重画 innerHTML，手上的按钮成游离节点 → 连点第二次没反应、焦点也丢。新增 `dataSqlSyncBatchTabs()`。
- **失败页签的空态文案**：`dataSqlEmptyHint('error')` 换掉「贴一段表格数据，写一句 SQL」（有 `data-i18n` 属性会被 applyI18n 重置，先摘属性）；新键 `dataSqlBatchTabFail` 14 语。
- **进度条 100% 后 0.9 s 自己收**（`dataSqlProgressHideTimer`）。
- **首屏 i18n 漏扫**：`DATASQL_I18N` 在 `18-flow.js` 末尾那次 `applyI18n()` 之后才定义 → 本页 placeholder / title 首屏全空，切一次语言才齐全。文件末尾补一次 `applyI18n()`；切语言时另外 `setOption('placeholder', …)` 同步给 CodeMirror（它只在建编辑器那一刻取一次）。

## SQL 分析页「编辑器周边」一轮（同日续）

用户连着提了 8 条：改不了类型 / 支持行级注释 / 示例挪到数据 / 示例做成选择框 / 去掉「改过了」/ 快捷语句挪到编辑器上方 / 搞成一行区分功能区 / SQL 记忆 + 压缩。

### 列类型下拉点不开（三个原因叠着）
- `open` 类加在 `.custom-select`（外层）→ CSS 只认 `.custom-select-options.open`，表现为「箭头翻过去、选项一个不出」。
- 面板里列清单是 `overflow-y: auto`，绝对定位的下拉被裁光 → 改 `position: fixed`，`dataSqlOpenTypeOptions()` 按触发器算 left/top，下方放不开翻到上面。
- 一次只开一个（十几列同时摊开没法看）+ 滚动 / resize / Esc 收起。

### `//` 行注释
- 编辑器侧与引擎侧要**同时**认：`dataSqlIsLineCommentStart()`（`--` / `//`）+ `sqlrun.js` 词法里同一个判断。只改一边就会出现「▶ 认得、执行报错」。
- `#` 故意不认：MySQL 当注释，但 SQL Server 的 `#临时表` 也是它，`SELECT * FROM #tmp` 会被吃成半句。
- `//` 染色：CodeMirror 自带 sql 模式只认 `--`，用 `markText(..., {className:'cm-comment'})` 在 `dataSqlSyncRunGutter()` 里跟 ▶ 一起刷（文本一改两边都得重算）。

### 示例收成下拉（数据标题行上）
- 两个坑：`09-convert.js` 有「点页面任意处收全部下拉」→ 触发器 / 选项都要 `e.stopPropagation()`；`#dataSqlWorkspace .pane-header { overflow: visible }`，默认 `hidden` 会把下拉裁掉。
- 导航搜索要能把下拉里的 `.custom-option` 当页内二级项（`08-nav-search.js` 选择器加 `, .custom-option`，`data.sample` 当 key）。

### 工具栏合成一行
- 三段：读数据（分隔符 / 表头）｜快捷语句｜执行（导入 SQL / 清空 / 运行），中间 `.datasql-tool-sep` 一条 1px 竖线（`flex: 0 0 auto` + 固定高 1.1rem，别让它被拉伸）。实测高 41、两条竖线、`run.bottom=113 < editor.top=131`。
- 状态栏「SQL 或数据改过了，点运行」整条删掉（结果面板顶上「已执行 …」本来就写明是哪一句）；`dataSqlNeedRun` 14 语键一起删。

### SQL 草稿记忆（压缩）
- 分档 `dataSqlDraftPlan(rawLen, gzipLen)`：≤24 KB 原样 → 压完 ≤128 KB 存 gzip+base64 → raw 本身 ≤128 KB 原样 → 否则 `skip`（宁可丢也不挤占布局 / 主题那些真要记住的配置）。
- `CompressionStream` 原生（宿主 CSP 不支持 wasm，别想引库）；无能力时 `dataSqlDraftUnsupported` 一次判定后永久降级，不反复 try。
- base64 分块 `0x8000` 转，`String.fromCharCode.apply` 对 MB 级必爆栈。
- **异步压缩要带序号**：`dataSqlDraftSeq`，落盘前比对，慢压完的旧结果直接丢，否则会盖掉新草稿。
- 800 ms 防抖；`visibilitychange`→hidden、`exitDataSqlMode()`、`dataSqlRun()` 三处强制 flush（关页 / 切页 / 跑之前各补一次）。
- 恢复只在框里为空时做，光标落到末尾。实测 40 KB → 516 B（0.013）、614 KB → 3852 B，新进程恢复出原文 + ▶ 标记。
