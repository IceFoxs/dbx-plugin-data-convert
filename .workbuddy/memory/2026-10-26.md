**实现**
- 顶栏最右加 `#navToggle`（32×32 图标按钮，`data-keep-title`），图标随布局切换：顶部显示"顶栏"图、左侧显示"侧栏"图。

**持久化（关键决策）**
- 查官方文档确认：DBX 工作台是 **opaque origin 沙箱，`localStorage` 会抛 SecurityError**，官方明确要求用 `window.dbxPlugin.storage`，需 `host.storage` 权限 + `capabilities.storage` 门控。
- manifest `permissions` 加 `host.storage`。
- 三级降级：宿主 storage → 浏览器 localStorage（dev/预览）→ 内存。键 `navLayout` = `top` / `left`。启动先同步 localStorage 预读（避免闪一下顶部），再 `await dbxPlugin.ready` 后 `storage.get('navLayout')` 校正。
- `set` 失败静默，不打扰用户。

**踩坑**
- **1440 宽下 10 个导航项变 8 个**：新按钮占 32px + gap，导致「更多」出现并再占 80px。实测 `.nav-links a` padding 从 `0.8rem` 收到 `0.65rem` 后 10 项全回来（navW 861 → 948）。左侧栏项单独 padding 不受影响。
- 左侧栏宽度用 `--nav-left-w: 13rem` 变量统一（`#navLinks` 宽 + `main-container` margin-left）。

**验证**

### 16:20 dev 模式记不住导航布局（用户：dev模式下好像没生效切换导航栏记忆）

查了 CLI：`dbx-plugin dev` 注入的 `dbxPlugin` 只有 `ready` / `context` / `locale` / `theme` / `request` / `invoke` / `stream` / `notify` / `sendBinary`，**没有 storage**；dev UI 是每个标签页一个 `<iframe sandbox="allow-scripts" srcdoc>`。实测这种沙箱里 `localStorage` / `sessionStorage` / `cookie` 全抛 SecurityError，只有 `window.name` 能跨刷新（srcdoc 重载保 name、新建 iframe 就丢）。

所以加了第三级兜底 `window.name`（记号 `dbx-nav:left|top`，保留原有 name 内容），启动同步读 `localStorage || window.name`，切换时三处都写。用 OOPIF flatten 会话在真 Chrome 里验证：沙箱内 localStorage 抛错 → 切左侧 → 刷新仍是左侧、切回顶部刷新仍是顶部。

### 21:20 二维码中心图标「上传后不生效」（用户报）

排查结论：图标链路本身是通的（file:// 与 dev 沙箱都验过 `<image>` 会出来），真正的问题是**纠错级别不够**。
- 用 jsQR 做遮挡回归：把中心按 `svgMarkup` 同一套比例（图标 22% + 呼吸位）抹白后解码，**L / M / Q 全部扫不出来，只有 H 能解回原文**。默认纠错是 M，所以贴了图标的码直接变成「看着有图、扫了没反应」。
- 修：`qrSetIcon()` 里把纠错自动顶到 `H`（抽出 `qrSetEcc()` 给 chip 高亮与状态一起改），toast 明说「图标已应用，纠错已调到 H」；`qrRun()` 在 `iconHref && ecc !== 'H'` 时再提示「可能扫不出来」。
- 顺带堵住三个静默失败点：① 原来 `!file.type.startsWith('image/')` 直接 `return`（MIME 为空就永远没反应）→ 改成按扩展名兜底 + 明确报错；② 上限 2 MB 太小且文案是「读取失败」→ 提到 8 MB 并说清大小；③ 原图直接当 data URI 塞进每张卡片的 SVG（照片 JPG 两三 MB，200 张卡片能把 DOM 撑爆）→ 先 `qrNormalizeIcon()` 缩到长边 256 的 PNG 再用。
- `drawToCanvas` 里 `if (icon && icon.naturalWidth)` 会让拿不到内在尺寸的图（部分 SVG）整块跳过 → 改成兜底 1×1 比例 + try/catch。
- 选文件框从 `hidden` 改成 `.qr-hidden-input`（`display:none` 的 file input 在部分 WebView 里 `.click()` 不弹框）。
- 验证：dev 宿主（OOPIF）里用 1200×1200 JPEG 上传 → 缩略图 256 px、`<image>` 1 个、纠错 chip 自动到 H、toast 正确。
