## 追加：三条解析/显示需求（同一天）

用户拿着真实接口返回提了三件事，逐条落地：

### 1. 智能解析（接口把 option 包在业务 key 里，还是字符串）

真实形状：`{"gantry_count_trend":{"echart_option":"{\"title\":…}","table_data":null,"biz_data":{}}}`。
原来的 `classify()` 只会看顶层，直接判 `unknown` → 报「画不出图」。

- 新增 `findInside(node, depth)`：递归下探（≤3 层），按「键名打分 + 内容打分」挑候选。键名分：`echart_option|chartOption|chartConfig|option|config|spec` 高，`echart|chart|graph` 中，`data|result|payload|rows|series` 低；内容分：完整 option 60、纯数据 20。字符串以 `{`/`[` 开头才尝试 `JSON.parse`（二次编码也认）。
- `parseText()` 先 `JSON.parse`，成功后自动 `unwrap`，返回 `{ value, via, layers, options }`。`via` 就是走过的键路径，UI 用它显示「已自动解析 xxx」（新键 `chartUnwrapped`）。剥不动就原样返回，交给 `classify` 报 shape。
- 注意：`findInside` 遇到「已经能用」的节点（option / points / pairs / map）立刻停，不会把 `series` 里的对象当根。

### 2. 一个 JSON 多个 options / 换行多个 JSON

- `collectOptions(value)`：BFS，预算 300 个节点、深度 4，命中 option 就停；返回 `[{ path, title, value }]`，`title` 取 `option.title.text`。`parseText` 里 `options.length ≥ 1` 就直接用它（第一个当默认）。
- 多份 JSON：新增 `splitJsonDocs(text)`，自己按括号配平 + 字符串/转义状态机切分，支持 NDJSON、`{…}{…}` 首尾相接、行间逗号、BOM、字符串里的括号，最多 200 段；切不动（半截）就返回 null，仍报 `json-invalid`。多段时 option 路径前缀 `#1` / `#2`。
- UI 新增 `#chartPick` 下拉（`chartPickWrap` 包一层，单图时 `hidden`），选项文字用 title、`title` 属性放路径；`chartRender(keepPick)` 在「只是切换图」时带 `true`，靠 `chartPickSig`（路径+标题签名）跳过重建，否则选中值会被重置回第一个（这个是冒烟测出来的真 bug）。
- 三段新文案 `chartPickLabel` / `chartPickTitle` / `chartUnwrapped` × 14 语言。

### 3. 图片不要拉伸

- 预览本来就 1:1（`echarts.init` 传 width/height，canvas 的 style 也是 px），真正的毛病是布局：`.chart-stage` 用了 `justify-content: center`，画布比面板宽时左半截被顶出可视区、且滚不回去（实测 1400 px 画布在 686 px 面板里 `scrollWidth` 只有 1052）。改成 `justify-content: flex-start` + `.chart-canvas { margin: auto; }`：装得下就居中、装不下从左排且能滚到头。
- 再加一层保险：`chartApply()` 里对画布与内部 canvas 用 `setProperty('max-width'/'max-height','none','important')`，防止宿主那条 `canvas{max-width:100%}` 把图压扁。
- 没有加 `object-fit: none`：canvas 是替换元素，HiDPI 下 `width` 属性是 CSS 尺寸 × dpr，`object-fit:none` 会按属性尺寸渲染再裁切，反而毁掉高清渲染。

## 22:10 像素比 / 放大查看 / shadcn 统一样式 / 导出状态

### 像素比（用户连发四条，核心诉求）
- 对照用户给的 node 参考实现（`echarts.init(canvas, null, { renderer:'canvas', devicePixelRatio })`），确定「像素比」= 渲染时的 `devicePixelRatio`。
- 工具栏 `#chartScale`（`.custom-select`，`select-compact`），1x / 2x / 3x，`data-label` 存触发器短标签、选项里 `.chart-opt-size` 标该档实际像素，`chartFillScale()` 在尺寸变化时重算；导出按钮 title 也带（`data-keep-title`）。
- 导出 PNG 改成 `chartRenderPng(option, w, h, ratio)`：临时实例 `devicePixelRatio: ratio` + `animation:false`，取图时**必须显式传 `pixelRatio: ratio`**（实测只传 1 时 zrender 给 700×400，不读实例 dpr）。
- `chartSafeScale()` 按 2400 万像素封顶，4096²@3x 自动降到 1x。
- **命名坑**：已有 `chartScaleNow(w,h)` 是预览缩放，新函数同名会被后声明的覆盖，症状是「下拉都对、取值永远 1」。改名 `chartPixelRatio()`。

### 放大查看（灯箱）
- 图表 `#chartPreviewBtn` + 双击画布 → 复用图片页的 `#imgLightbox`，出图也按所选像素比，标题写真实像素 + 倍率。

### 导出「不生效」根因
- 权限与 aes-tools 完全相同，排除权限。
- **dev 模式本来就不支持**（用户确认）：dev 宿主没有 `fileTransfer`，iframe `sandbox="allow-scripts"` 禁下载。
- 真正的产品缺陷：`saveTextFile` / `saveBinaryFile` 失败也返回 `browser`，调用方一律 toast「已导出」→「点了没反应还说成功」。现在四态 `host/browser/cancelled/failed` + `saveToast()`，`beginSave` 改为同步取 Promise + 失败 `cancel(handleId)`（照 aes-tools）。
