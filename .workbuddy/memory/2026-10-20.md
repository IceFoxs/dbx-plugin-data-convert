## 项目体检（静态分析，未改代码）

DBX 前端插件，v0.1.1，纯前端单文件实现：`ui/index.html` 1740 行（CSS 58-624、HTML 625-789、JS 791-1737）。

关键发现（供后续修复参考）：
- **构建链断了**：`scripts/build.sh` / `run.sh` 前 20 行是从带 Rust sidecar 的模板复制来的，引用不存在的 `backend/target` 与 `shared/sdk/rust/dbx-plugin-sdk`；`sdk_root_shim.sh` 直接 exit 1，配合 `set -euo pipefail`，发布 workflow（`package-command: ./scripts/build.sh`）必然失败。
- **`ui/json/index.js` 是 ESM**（`export default`），却用经典 `<script src>` 加载 → SyntaxError，`window.stringify` 永远走 index.html 13-17 行的 polyfill，`maxLength:80` 实际不存在。
- **重复 id** `outputLabel`（739 与 754），`getElementById` 取第一个，格式后缀写进了 pane 标题而非 result-header。
- **XML 往返不保真**：根元素名被丢弃（`<config>` → 子节点对象 → 回写 `<a>1</a>`）；数字/布尔跨 XML 变字符串；顶层多键对象产出多个并列根（非法 XML）。
- **diff 行号错位**：行号在格式化文本上算，却打在原始文本上；LCS 二维数组无规模上限。
- properties 值全为字符串；根级纯数字键未回写（1502-1503）。
- 13 套 i18n 字典只展示 3 种（`displayLangCodes`），manifest.localizations 与 UI 字典双份文案源。
- `.DS_Store` ×4 被打进 `.dbxp`；`<title>` 是开发遗留文案。

## 布局修复（用户反馈「左右编辑器没固定」）

**症状**：右侧编辑器被内容顶出视口底部（页面静默裁切），左右两栏不等高。根因是两栏结构不对称（右栏多一行 `result-header`，左栏多一行按钮），且 `.editor-container .CodeMirror { height:100% }` 在 flex 列里叠加 header 高度后溢出、`overflow:hidden` 直接裁掉底部。

**改法（保持单文件形态）**
- `.workspace-grid` 改 `grid-template-columns: repeat(2, minmax(0,1fr))` + `grid-template-rows: minmax(0,1fr)` + `overflow:hidden`；`.main-container` / `.pane` / `.editor-container` 全部补 `min-height:0`。
- 两栏结构对齐为 `pane-header + editor-container`：`result-header` 删除，输出格式改为 pane 标题旁的 `.pane-badge`（`updateOutputLabel()` 只写 `JSON/YAML/XML/PROPERTIES`）；「执行转换」移入顶部工具栏（`.toolbar .btn-primary { flex:0 0 auto }`）。
- `.error-bar` 改为 `position:absolute` 浮在编辑器底部，出现/消失不改变高度；`.textarea` 改 `flex:1 1 0`；`.CodeMirror` 加 `flex:1 1 0; min-height:0`。
- 响应式：`@media (max-width:1100px)` 面板按钮只留图标（title 仍在）；堆叠断点从 900 下调到 768，避免半宽面板被压扁。
- `docs/screen.png` 换成修复后的界面；CHANGELOG 0.1.2 补一条布局修复。

**验证**：`tests/ui.smoke.js` 增至 15 项（新增两栏结构一致 / errorBar 在容器内 / 行高 1fr 三条布局守卫）。另用 puppeteer-core + 本机 Chrome 跑真实浏览器校验（临时脚本在 /tmp/dbx-smoke，未入仓）：1440x900 两栏均 682px、底边 876 < 900；1900/1280/1024/900/800/760/420 宽度组合均无溢出；暗色主题已目视确认。改后重新打包 `dist/...0.1.2-universal.dbxp`。

## 第二轮：模拟数据 / diff / properties

**「模拟数据」输出 null（回归）**
- 根因：`genMockBtn` 先 `currentDataObj = mock`，再 `inputText.value = serializeData(...)`；赋值触发 CodeMirror `change`，回调无条件 `currentDataObj = null`，下一行序列化就拿到 `null`。
- 修复：`inputEditor.on('change')` 在 `suppressAutoConvert` 期间只同步文本、不清缓存也不排自动转换；模拟数据改为先算好两份文本再写回。

**JSON 输出统一 2 空格**
- `ui/json/index.js` 是 pretty-compact 实现，短对象会被压成一行，点「格式化」像没生效。现已删除该文件与 `ui/json/` 目录，`serializeData(obj,'json')` 直接 `JSON.stringify(obj,null,2)`。
- 注意：这恢复了 0.1.1 的真实行为（当年该文件是 ESM 加载失败，一直在走 polyfill）。

**diff 抽模块 + 行号修复（ui/js/diff.js）**
- `diffLines(textA, textB, {maxCells, lookahead})` → `{ops, mode, stats}`，每个 op 自带 1-based `oldLine/newLine`；`sides(ops)` 直接给两栏 0-based 行号。
- 先裁公共前后缀再 DP；DP 用 `Uint32Array`，中间段 `N*M > 2,000,000` 时降级 `greedyDiff`（按行文本建索引 + 64 行窗口重同步），5000 行全不同约需 <1s。
- UI 侧：比较文本与展示文本统一（JSON 先规范化），不再用自己累加的 oIdx/nIdx；两栏标题加 `−删/+增` 徽标；降级时 toast 提示（新增 i18n key `diffLarge`，14 套字典）。

**properties 下标增层/丢失**
- 根因：`key.split(/\.|\[|\]/)` 把「点号后的数字属性」和「方括号下标」混为一谈，`0.0[0][0]…` 往返会多套一层数组。
- 修复：`propertyTokens()` 先按 `.` 分段，再单独匹配 `[n]`；点号后数字永远是对象键，`[n]` 才是数组下标。`objToProperties` 跳过数组空洞。
- 该文件往返已逐字幂等，已加入用例。

**测试现状**：converters 37 / diff 13 / ui.smoke 21，`build.sh` 跑前两套；CI 增加 diff 步骤，并把「经典脚本检查」从已删除的 `ui/json/index.js` 换成 `ui/js/diff.js`。
