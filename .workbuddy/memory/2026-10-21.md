## 暗色模式跟随 DBX 主题（真实环境复现与修复）

- 用户截图：DBX 切到暖棕暗色皮肤后，插件背景被宿主 `--color-*` 令牌染暗，但导航文字、边框、按钮、CodeMirror 语法主题仍是亮色的一套，导航几乎读不出、编辑器深字压深底。
- 根因：插件只在 `dbx-plugin-env` 事件里 `setAttribute('data-dbx-theme', env.theme.appearance)`，**初始化时从不读 `dbxPlugin.theme`**，完全依赖宿主替它写 `data-dbx-theme`。宿主若没写（旧版本 / 某些皮肤 / 独立预览），`[data-dbx-theme="dark"]` 不命中，暗色变量整套失效；而背景走 `:root` 的 `var(--color-background)` 已被宿主 token 染暗，于是「一半暗一半亮」。
- 修复（`ui/index.html` 第 2 节）：
  - `applyHostTheme(theme)`：写 `data-dbx-theme` + `color-scheme`，并把 `--color-* / --radius-* / --font-*` 令牌写到 root（宿主已注入时重复设置无害）。
  - 三级兜底 `detectAppearance()`：`theme.appearance` → `data-theme`/`data-color-scheme` 属性 → `--color-background`（兼容 `--background`）亮度 < 0.45 → `.dark` class → 系统偏好。
  - 初始化 `await dbxPlugin.ready` 后立即 `applyHostTheme(dbxPlugin.theme)`；监听 `dbx-plugin-init` 与 `dbx-plugin-env` 实时跟随；独立浏览器下监听 `prefers-color-scheme` 变化。
  - 暗色变量改为 `var(--color-*, 内置冷灰)`，自定义皮肤（暖色）也能一致；`:root` 与暗色块都补 `color-scheme`。
  - `syncEditorTheme()` 现在覆盖 `[diffLeft, diffRight, cmpLeft, cmpRight]`；`cmpLeftEditor/cmpRightEditor` 的 `let` 声明从对比页段提前到 CodeMirror 段，避免首次调用踩 TDZ；`ensureCompareEditors()` 创建后补一次主题同步。
- 验证（真实 Chrome + 模拟宿主）：A 有 theme 不写属性 / B 无 theme 仅暗 token / C light / D 无宿主系统暗 / E 只写属性 —— 五种场景 `data-dbx-theme`、bodyBg、navColor、编辑器 `cm-s-material-darker` 全部正确，无 JS 报错；暖棕皮肤下导航对比度 6.16:1。
- 用例：`tests/ui.smoke.js` 增至 **43** 项（新增「宿主只给 theme 时仍进暗色」「暗色下编辑器切 material-darker」，用独立 JSDOM 实例注入 `dbxPlugin` stub）。
- 文档/产物：CHANGELOG 0.1.3 补修复条目、README 中英更新主题说明与用例数；新增 `docs/screen-theme-host-dark.png`、`docs/screen-theme-host-dark-compare.png`；重新打包 0.1.3。

## 明暗切换的过渡（整页渐变 + 首屏不闪）

- 体检发现的问题：切主题时只有 `body` 有 transition，导航/工具栏/编辑器底色**瞬间硬切**，300ms 内出现「一半旧色一半新色」；首屏也没按宿主主题落定。
- 走过的弯路（重要经验）：
  1. 给 `*` 挂 `transition: background-color/border-color/color ... !important`：颜色确实一起变了，但**文字色每帧只走一点点**（300ms 走了 25%），因为子元素继承的是父元素正在动画的 `color`，每帧重启自己的过渡 → 永远追不上。实测 p90 帧耗时也从 19ms 涨到 50ms。
  2. 只关掉 `.CodeMirror *` 的过渡能回到 60fps，但继承链上其它文字（导航、按钮）仍然滞后。
- 最终方案：`@property` 把派生颜色变量注册成 `<color>`（`--bg-base/--bg-card/--text-main/--text-muted/--border-light/--accent-bg/--accent-hover/--primary/--primary-text`），切换时由浏览器插值这些变量本身；同时 `html.theme-anim *` 关掉元素自身的 transition（避免再追一次）。实测 body/导航/按钮/编辑器底色全部 300ms 内同步到位，帧耗时 p50 17ms、p90 18ms、max 19ms（与不加动画持平）。
  - 注意：不做 `@supports` 判断，旧内核不认识 `@property` 时自定义属性不插值，自然没有动画，不会出现半套。
  - 宿主令牌为 `hsl()` / `oklch()` 也验证通过（不会退回 initial-value）。
- CodeMirror：主题 class 一换，语法配色是重建的，文字色无法过渡。改为**延后到过渡中点（0.34×300ms ≈ 102ms）**再 `setOption('theme')`，那时底色在中间调，新旧文字色都看得清；`syncEditorTheme()` 里去掉多余的 `refresh()`（`setOption` 内部已经刷新过），只有主题没变（仅换皮肤令牌）时才手动 refresh。
- 首屏：`<head>` 里加一段内联脚本，同步读 `window.dbxPlugin.theme`（宿主 preload 注入，首帧就存在）先定 `data-dbx-theme` 并把 token 落到 root，取不到才看系统偏好；`applyHostTheme` 首次调用不带动画（`themeBooted`），所以不会出现「白底淡入深色」。实测暗色宿主+亮色系统，首帧就是 `rgb(48,43,33)`。
- 其它：`applyHostTheme` 现在会比较 token 是否真的变了（只换皮肤也过渡）；新增 `MutationObserver` 监听 `data-dbx-theme`，宿主直接写属性也能同步编辑器主题（用 `lastAppliedTheme` 区分是不是自己写的）；`prefers-reduced-motion` 下不挂过渡类、编辑器主题也立即切换。
- 顺手修：`.CodeMirror-gutters` 背景改透明 + 右边框用 `--border-light`，不再吃主题里的硬编码 `#f7f7f7/#212121`，换主题时不会闪出一条缝。
- 验证：`theme-transition-check.js` 25 项（首屏无白闪、过渡中间值连续、编辑器底色同步、过渡类清理、快速连切、对比页两块编辑器、宿主直写属性、只换皮肤、reduce-motion）全过；`theme-perf.js` 帧耗时对比；`first-paint.js` 三种首屏场景；单元 72 + jsdom 冒烟 **50** 项；对比页/导航/文本模式旧脚本全部回归。

## 0.1.4 反馈修复：整段 SQL 粘回来的尾巴 / 纯数字加引号
- 截图反馈一：`... IN (...)\n) and service_name='iss-sts';` 整段粘回来时，尾句被当成最后一个值（输出里多出 `'and service_name=''iss-sts'''`，91 个值里有一个是垃圾）。根因是 `stripSqlHead()` 只切了 `IN (` 之前的头部。
- 修法：新增 `matchParen()`（跳过引号内的括号），`stripSqlHead()` 按括号配对只取括号内区间；`VALUES ('a'),('b')` 后面紧跟的括号会连成一整段；括号没闭合仍走老逻辑；只贴 `('a','b')` 这种没头的也按配对收尾。
- 截图反馈二（"纯数字要支持加'"）：真因是三个开关 `#sqlDedup/#sqlMultiline/#sqlNumeric` 只被 `readSqlOptions()` 读取，从没接 `change` 事件——取消勾选要等下一次敲键盘才生效，看起来就是「勾了没反应」。已补 `change → runSql`。
- 同时把默认反过来：`DEFAULT_OPTIONS.numeric` 改为 `false`、`#sqlNumeric` 默认不勾，纯数字默认带引号（ID 列多是 varchar）；要裸数字再勾上。单测/冒烟同步改期望值。
- 顺手修 `@media (max-width: 1100px)` 里 `.pane-actions .btn span { display:none }`——这些按钮只有文字没有图标，藏完只剩空框（我本地 1080 截图复现），改成收紧 padding/字号。
- 用例：单测 113（sqlgen 41），冒烟 62 → 65；0.1.4 重新打包。
