## 21:35 图表宽高输入体验修复（不改版本号）

用户先反馈「输入体验不好」（截图：`type="number"` 带 spinner），再澄清「输入之后老是变」——根因是输入过程中值被弹回。

### 根因
`chartRender` 里 `if (size.wCode) { chartWidthInput.value = ... }` 会在**输入过程中**把越界中间值回写进输入框。用户想把 700 改成 900，逐字符经过 9 → 90，每个 `input` 事件 → 防抖 320ms → `chartRender` → `clampSize('9')` 得 9、`9 < 80` → 回写成 `80`，数字根本敲不进去。

### 改动
- `ui/index.html`：
  - 输入框 `type="number" step="10"` → `type="text" inputmode="numeric"`，去掉原生 spinner（CSS 补 `appearance:textfield` + `::-webkit-*-spin-button` 隐藏兜底）。
  - `chartRender` 里删掉「越界回写输入框」，只保留提示；预览仍用 `clampSize` 夹取后的值渲染（不回写）。
  - 新增 focus 全选 + blur 夹取：聚焦 `el.select()`；失焦时 `clampSize` 结果与当前值不一致（空/非数字/越界）才回写一次并 `chartSchedule()`。
- `tests/ui.smoke.js` 加一条回归：「改宽高：输入过程中不被弹回，失焦才夹取边界」（`win.Event` 不能写成全局 `Event`，否则 jsdom 报 "parameter 1 is not of type 'Event'"）。

### 验证
- `chart.test.js` 76/76、`ui.smoke.js` 219/219、`npm test` 全绿。
- 真 Chrome CDP（重建 `/tmp/imgh/cdp.js`，Node 22 原生 WebSocket）复现：输入 9→90→900 全程不被弹回，最终 900 × 400；失焦 9→80、5000→4096 正确夹取；无未捕获错误。
