### 内存 / 性能关键改动（第 6 条）
- **懒拼全量文本**：`IMG_LAZY_TEXT = 2 * 1024 * 1024`；Base64 超过阈值时 `imgState.text = ''`、只拼 200 K 字符切片做预览，`textLen` 记真实长度，导出时才临时拼一次、写完立即释放。
- **objectURL 预览**：`URL.createObjectURL(file)` 代替把上千万字符的 data URI 塞 `<img>`；`imgReleasePreviewUrl()` 在清空 / 换图 / 重置时 `revokeObjectURL`。
- **`normalizeBase64` 快路径**：`/^[A-Za-z0-9+/]+={0,2}$/` + `%4===0` 直接返回，躲开 8 次 26 MB 全量替换（9.33 MB：27 ms / `parseInput` 45 ms）。
- **`encodeUtf8` 预分配** `Uint8Array(len*3)` + `subarray`；编码器 8 KB 一段 `fromCharCode`。
- 实测（headless CDP，file:// 直开 `ui/index.html`）：DOMContentLoaded 497 ms（冷启）、堆 9.5 MB、535 节点；进图片页 63 ms；**8 MB 图编码 234 ms，编码后堆仍 9.5 MB、`imgState.text` 为空、预览 200 000 字符**；进出图片页 5 次，堆与节点数完全不变（无泄漏）。

## 按钮上的英文 tooltip（同日第四批）

## 全局拖放不生效的根因（已修）

**DBX 是 Tauri v2 应用**（`/Applications/DBX.app` 的 Resources 里只有 icon.icns，二进制里 `tauri://drag-enter` / `drag-over` / `drag-drop` / `drag-leave` 齐全，wry + WKWebView）。Tauri 的 `dragDropEnabled` 默认为真，系统文件拖放被原生层接管，**页面里的 `dragenter` / `dragover` / `drop` 根本不会触发** —— 之前只在 jsdom 里派发过 drop 事件，测得过但真机永远没反应。

### 正确解法：走宿主 fileTransfer（参考 icefoxs/dbx-plugin-aes-tools 的实现）

```js
window.dbxPlugin.fileTransfer = {
  onDrop(cb)                 // cb([{ name, handleId, size?, contentType }])
  onDragState(cb)            // cb(isDragging) → 控制蒙层
  read(handleId, off, len)   // → { dataBase64, eof }，必须自己按块拼
  cancel(handleId)           // 放弃这个句柄
  beginSave/write/finish     // 导出用（本插件图片导出已在用）
}
window.dbxPlugin.capabilities.fileTransfer.drop / .beginSave  // 能力开关
```

三个坑：
1. **`fileTransfer` 只在 `dbxPlugin.ready` resolve 之后才挂上**，DOMContentLoaded 时读是 undefined。aes-tools 也是把 `setupDropListeners()` 放在 `ready.then()` 里。
2. 宿主只给 `handleId`，没有 File 对象；读回 bytes 后 `new File([bytes], name, {type})` 就能复用图片页 / 表格页 / 文本页的既有逻辑。
3. 读取要分块（256 KB），一次 `read` 全文件会让 base64 字符串一次性膨胀。

### 实现（ui/index.html 第 13 节）
- `hostDropAvailable()` → `setupHostDrop()`：`onDragState` 控蒙层，`onDrop` 校验数量（10）→ `routeBatch` → 按类型定上限（图片 10 MB / 表格 20 MB / 文本 2 MB）→ 逐块读 → 路由。
- 图片页、文本页一次只用一个文件，所以 `need = kind === 'sheet' ? list.length : 1`，多拖的不读进内存。
- 一次拖入总预算 40 MB；超了提示 `flowDropTooBig`。
- 浏览器路径保留作兜底（直接开 index.html 预览）；`claimDrop(source)` 按「来源不同 + 800 ms 内」去重，同来源连拖两次不受影响。
- 新增 `FLOW_I18N.flowDropTooBig` / `flowDropFail`（14 语）。

### 数据
- 冒烟新增 9 条「宿主 fileTransfer 路径」用例（独立 jsdom 实例注入 mock），166 → **175**；单测 691 不变。
