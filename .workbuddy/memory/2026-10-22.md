### Bug：「最多条数」下拉点了只有箭头翻转
- 根因：下拉菜单是 `position: absolute; top: 100%`，但 `.custom-select` 自己**没有** `position: relative`；顶栏那两只借了外层 `.select-group` 的定位才正常，表格页这个没有定位祖先 → 菜单以 `.main-container` 为参照，被算到页面底部，再被 `overflow: hidden` 裁掉。

- 排查技巧：headless 的 `--virtual-time-budget` 下 **CSS transition 时钟不推进**，`visibility/opacity` 会卡在过渡起点（连 inline `!important` 都压不住），必须在点击前 `style.setProperty('transition','none','important')` 才能测到真实显隐；菜单位置用 `getBoundingClientRect()` 和触发器比对才定位到「跑到 y=617」。

## 0.1.5：图片 ↔ Base64 页 + 内存/加载性能收尾

### 用户诉求（原话）
1. 「考虑纯base64字符串的情况」→ 解码要认裸 Base64；
2. 「图片转导出支持纯base字符串，支持自动解析纯base64解析为图片」→ 编码可只导裸串，解码自动出图；
3. 「展示base64不完整时，复制按钮提示请导出文件查看数据」→ 截断时复制不能说「成功」；
4. 「支持svg吗？」→ 文件 / Base64 / DataURI / **SVG 源码** 四路都要通；
5. 「svg可以不测大文件」→ 大文件压力测试只对位图做；
6. 「考虑dbx加载该插件时和使用时性能问题，避免主程序崩溃」→ 加载与运行时都要省内存。

### 内存 / 性能关键改动（第 6 条）
- **懒拼全量文本**：`IMG_LAZY_TEXT = 2 * 1024 * 1024`；Base64 超过阈值时 `imgState.text = ''`、只拼 200 K 字符切片做预览，`textLen` 记真实长度，导出时才临时拼一次、写完立即释放。
- **objectURL 预览**：`URL.createObjectURL(file)` 代替把上千万字符的 data URI 塞 `<img>`；`imgReleasePreviewUrl()` 在清空 / 换图 / 重置时 `revokeObjectURL`。
- **`normalizeBase64` 快路径**：`/^[A-Za-z0-9+/]+={0,2}$/` + `%4===0` 直接返回，躲开 8 次 26 MB 全量替换（9.33 MB：27 ms / `parseInput` 45 ms）。
- **`encodeUtf8` 预分配** `Uint8Array(len*3)` + `subarray`；编码器 8 KB 一段 `fromCharCode`。
- 实测（headless CDP，file:// 直开 `ui/index.html`）：DOMContentLoaded 497 ms（冷启）、堆 9.5 MB、535 节点；进图片页 63 ms；**8 MB 图编码 234 ms，编码后堆仍 9.5 MB、`imgState.text` 为空、预览 200 000 字符**；进出图片页 5 次，堆与节点数完全不变（无泄漏）。

## 粘贴按钮「乱跳」+ 国际化补全（同日第三批）

### 1. 用户反馈：「点击粘贴回跳转功能，不正常」
截图是「图片转 Base64」页，箭头指向「粘贴」。

- **根因**：编码页的 `imgPasteBtn` 读到文本型剪贴板时直接 `setImgMode('decode')`——用户只想贴张图，页面自己换页签；剪贴板恰好是一段 Base64 时尤其像"按钮乱跳"。
- **改法**：编码页按钮只处理图片；识别到 Base64 只把文本塞进（隐藏的）`imgInput` 并提示「已放到「Base64 转图片」页」，切不切由用户点页签。解码页补上同一个按钮（`imgPasteBtn.hidden = false`），点了直接贴文本并 `imgDecodeNow()`。
- `navigator.clipboard.read()` 不可用 / 被拒（DBX webview 常见）与"剪贴板真的空"分开提示：前者引导 `Ctrl+V` 或拖入，后者才说「没有图片」。新增 `imgClipImageDenied` 标记。
- 新增 `imgReadClipboardImage()` / `imgReadClipboardText()`：后者先走宿主 `dbxPlugin.clipboard.readText`，失败再退 `navigator.clipboard.readText`。
- **保留** 编码页 `Ctrl+V` 自动切解码（这是用户上一轮明确要的"自动解析"），只去掉按钮的隐式跳转。
- 真浏览器（CDP + 伪造 clipboard）验证：文本粘贴后仍在编码页、toast 正确；图片粘贴正常；解码页按钮存在且能出图。

## 按钮上的英文 tooltip（同日第四批）

用户发截图：图片页鼠标停在「粘贴」上，弹出英文 "Paste"，压住旁边的「选择图片」，要求「优化一下这个，取消提示」。

- **排查**：源码里 `#imgPaste` / `#imgPickTop` 都没有 `title`（git 历史里也从来没有 `title="Paste"`），装到 `~/Library/Application Support/com.dbx.app/plugins/.../0.1.5` 的版本也没有。用 CDP 打开页面 dump 所有 `[title]`：image 页两个按钮 title 为 null，而 SQL 页 `#sqlPaste` 有中文「粘贴」。
- **结论**：这是**宿主补的**——插件里凡是没写 `title` 的按钮，DBX 会用它自己的词表补一个，于是中文界面冒出英文 "Paste"；写了 `data-i18n-title` 的按钮会被我们自己的中文文案覆盖，所以只有图片页这两个「裸按钮」露出来。
- **改法**：`stripHostTooltips()`（`ui/index.html`，紧随 `applyI18n` 定义、init 里调用）：摘掉 `button[title]` 中既没有 `data-i18n-title` 也没有 `data-keep-title` 的 title；用「加载后 sweep + 捕获阶段 pointerover + MutationObserver(attributeFilter:['title'])」三层兜住宿主的各种补法。`#imgExport`（动态显示导出格式与后缀）和 `#navConvertTrigger`（显示当前格式对）标 `data-keep-title` 放过。
- 顺带修 `outputResultLabel.title` 硬编码英文 `Result Output (YAML)` → 跟随 `currentDict.outputLabel`。
- **验证**：CDP 实测 —— 手动 `setAttribute('title','Paste')` 后 50 ms 被观察器摘掉；`pointerover` 路径也摘掉；`#imgExport` 的「导出 DataURI → .txt」保留；`#copyBtn` 的中文「复制」保留。冒烟新增 1 条（107 项全绿）。单测 241 条、i18n 19 条不受影响。
- **打包**：`dist/io.github.icefoxs.data-convert-0.1.5-universal.dbxp` 已重打，包内含 `stripHostTooltips`。

## 「Paste」气泡的真因 + 取消图片页粘贴按钮（同日第五批）

### 关键更正
上一批把「Paste」当成宿主补的 `title`，加的 `stripHostTooltips()` 并没有解决问题——用户回「还是不行」，并补充「左键点击弹出 Paste」。真因是 **WKWebView（DBX 跑在 macOS Tauri/webview 里）的剪贴板授权气泡**：页面一调 `navigator.clipboard.read()`，WebKit 就在按钮旁边浮一个自己的 Paste 按钮让用户再点一次。所以它不是 tooltip，拦 `title` 当然无效。

### 用户决定：「图片转换取消粘贴按钮」
- 删掉 `<button id="imgPaste">`（图片页编码/解码共用的那个），连带删掉 `imgPasteBtn` 引用、`imgReadClipboardImage()`、`imgReadClipboardText()`、`imgClipImageDenied` 与点击处理（共 78 行）。
- `navigator.clipboard.read()` 现在全项目 0 处调用；贴图只走 `Ctrl/Cmd+V`（`paste` 事件直接拿 `clipboardData.files`，不触发授权气泡）与拖拽，空状态本来就写着「也可以 Ctrl / Cmd + V 直接粘贴截图」。
- 删掉 4 个随之失效的 i18n 键（`imgTipPasteB64Ready` / `imgTipPasteNoText` / `imgTipPasteEmpty` / `imgTipPasteUnsupported`），14 种语言共 56 条，i18n 测试仍 19 条全绿。
- `stripHostTooltips()` 保留（成本可忽略，顺手防宿主给按钮补英文 title），但 CHANGELOG 里不再把它当主因。
