## 搜索框在宿主里的中文输入法问题（0.1.9 修复）

用户报：搜索框输入中文后按数字键选词没反应；明确「在 DBX 宿主里」、且「web 模式下没有问题」。

- 定位：`navSearchRender()` 绑在 `input` 上，组词中每次按键都重排；一旦 `value` 读到空（或用户清空），走 `navSearchClose()` → 清 `value` + 移除 `body.nav-searching`（顶部布局下 `.nav-search-wrap` 直接 `display:none`）→ 输入框失焦。Blink 容忍，WebKit（宿主）直接撤掉候选窗，之后数字键/回车全失效。这同时解释了之前「按回车搜索框消失」。
- 改法（`ui/js/app/08-nav-search.js`）：
  - 新增 `navComposing` 标记，`compositionstart/end` 维护；组词期间 `navSearchRender()` 直接 return，`input` 监听也跳过，`compositionend` 后才按上屏文字搜。
  - 拆出 `navSearchHideList()`：只收下拉、复位 aria；空值走它，不再退出搜索态、不清值。
  - `navSearchClose()` 在组词中不清 value；`blur` 与 `navSearchOpen()` 都会复位标记（防卡死）。
  - keydown 判断加 `navComposing`（有的宿主不给 `isComposing` / `keyCode 229`）。
- 测试：冒烟 +3（组词期间不重排；空值只收下拉；组词中数字键不打断）。298 → 300。

## 数据统计页第二轮（单元格复制 / 选列 / 懒加载）
- **点单元格即复制**：预览表与结果表都用「表上委托」（表每次重算整块重画，逐个 td 绑会全丢）。`dataset.copy` 存「要复制的原值」——结果表的空分组画成「—」，复制必须是空串。`statsFlashCell` 只让最新一格闪（前一个立刻退），700ms 后收。

## CI 修红（两处，都不是测试本身挂了）
- **第一次红在「装依赖」**：`package-lock.json` 里 36 个 tarball 地址被本机 npm 写成了 `mirrors.cloud.tencent.com`，GitHub 的 runner 连不上，`npm install` 跑 1m31s 后以 **112 / 152** 退出（不是 1，看板只报 1 error，特别像测试挂）。修：锁文件换成 `registry.npmjs.org`（integrity 已核对，镜像与公共源同一份 tarball），另加 `.npmrc` 的 `replace-registry-host=always`——这样本机 `npm install` 再写回镜像也不会影响 CI（默认值 `npmjs` 只替换 npmjs 那个 host）。CI 改用 `npm ci`。

## duckdb-wasm 可行性评估（未落代码）
- 结论：**当前宿主里所有 wasm 都跑不了**，不是 duckdb 的问题。宿主沙箱 CSP（plugin-cli `dev-runtime/runtime.mjs` 里 `sandboxDocument()` 与正式宿主同一模板）：
  `default-src 'none'; script-src 'unsafe-inline' blob:; style-src 'unsafe-inline' blob:; img-src data: blob:; font-src data: blob:; media-src data: blob:; connect-src 'none';`
  缺 `'wasm-unsafe-eval'` → Chromium（Windows/Linux 的 DBX、dev 宿主、浏览器预览）编译 wasm 直接 `CompileError`；`connect-src 'none'` → 连 `fetch(blob:)` 都是 `Failed to fetch`（duckdb 默认就靠 fetch 拿 wasm）。
- 实测（headless Chrome + 同一份 CSP，`/tmp/csp-wasm-test.html`）：`new WebAssembly.Module` FAIL、`instantiate` FAIL、`fetch(blob:)` FAIL、blob Worker **能建**（worker-src 回落到 script-src 的 blob:）但 worker 里编 wasm 同样 FAIL。macOS 的 WKWebView 对 wasm 历来宽松（Safari 不按 CSP 拦），所以会出现「mac 能跑、Windows 白屏」，不能押。
- 体积（@duckdb/duckdb-wasm 1.29.0）：`duckdb-mvp.wasm` 40.6 MB / `duckdb-eh.wasm` 35.6 MB / `duckdb-coi.wasm` 35.3 MB（coi 还要 COOP+COEP 跨源隔离拿 SAB，沙箱没戏）；worker 760~821 KB；主模块 30 KB。现在 `.dbxp` ≈ 1 MB，加进去按 4 倍压缩估 9~11 MB；`ui.readAsset` 走 base64 一趟 48 MB 字符串，`<script type="text/plain">` 内联能把 36 MB 塞进 srcdoc，两条都不现实。
- 备选：① 统计页已能吃管道分隔（`stats.js` 的 `CANDIDATES` 就有 `|`），单列分组今天就能答「按第 2 列汇总金额」；② 要任意 SQL 就在 `stats.js` 上加小解释器（SELECT/WHERE/GROUP BY 多列/HAVING/ORDER BY/LIMIT，AST 复用 `colStats`），零依赖零体积；③ alasql ~400 KB 纯 JS（无 wasm，CSP 无关）但有方言怪/维护弱；④ 真要 DuckDB 全套就上 sidecar（SDK 支持 Rust/Go），别塞前端 wasm。
