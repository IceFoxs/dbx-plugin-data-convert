## 拖拽排序在 DBX 里不生效（HTML5 拖放被宿主接管）

**现象**：用户报「拖拽改变导航栏顺序在 dbx 里不生效」。浏览器（本地 http 起页面）里能拖，装进 DBX 就完全没反应——行没有跟手的反馈、也没有落点。

**原因**：导航设置面板的行用的是 HTML5 拖放（`row.draggable = true` + `dragstart` / `dragover` / `drop`）。DBX 是 Tauri 应用，原生拖放由 WebView 层接管（同一个原因让文件拖入必须走宿主的 `onDragState`），页面里的拖放事件根本不触发。所以不是 CSS 挡住、也不是 `dataTransfer` 的问题，`:hover` 和箭头按钮都正常。

**改法**（`ui/index.html` 3.7 节）：
- 整段换成 Pointer 事件：`pointerdown` 记起点 → 位移 ≥ 4 px 才算拖（防止点一下就被当成排序）→ `pointermove` 里按每行中线找落点、直接 `insertBefore` 挪 DOM（视觉即时）→ `pointerup` 按 DOM 顺序落库再 `navPanelRender()` 一次（箭头禁用状态跟着新顺序）。
- 监听挂在 `document` 上并走捕获阶段：指针滑出面板甚至滑出窗口也能收到 `up`，不会卡在「拖拽中」。`navClosePanel()` 里主动 `navDragEnd()`，Esc / 点遮罩中途关闭不会留下监听。
- 置顶块与非置顶块之间不许互相插队（`navDragSameGroup()`），跨块仍用置顶按钮。
- 触屏只认左侧抓手（`.nv-grip { touch-action: none }`），否则整行可拖会把列表滚动吃掉；`.nv-row` 加 `cursor: grab` / `user-select: none`，拖动中 `body.nv-sorting` 统一 `grabbing` 光标。
- 删掉 `row.draggable`（改 false），保留 `NV_DRAG_EVT`，没 `PointerEvent` 的老宿主退回鼠标事件。

**测试**：冒烟 +4（最新四条：按住行往上拖→拖动中顺序就变、松手落库、`dragging` / `nv-sorting` 进出；拖到置顶块上方也跨不过去；只点不拖 / 按在按钮上不起拖；拖到一半按 Esc 关面板顺序照样落库且监听收掉）。jsdom 不做布局，临时把 `.nv-row` 的 `getBoundingClientRect` 桩成「30px 一行按索引堆叠」，测试结束还原。冒烟 269 → 273。
**真 Chrome 验收**（`/tmp/navdeck4/drag-check.js`，CDP `Input.dispatchMouseEvent` 发真实鼠标）：`navChart` 从第 7 行拖到置顶块之后首位，拖动中 DOM 已是 `navCompare,navSql,navChart,…`，松手后 `localStorage.navCustom` 落库，刷新后仍在；截图确认拖动行半透明、无文字选中。

**物料**：CHANGELOG 0.1.8 修复段新增 1 条（置顶）、工程化把冒烟条数改 18 条 / 273；`.dbx-store.json` releaseNotes 补一句（宿主里拖拽走 pointer）。README 中英原文已经写了「拖动行」，无需改。版本仍 0.1.8，未提交。

## index.html 拆分（用户 2026-10-27「将index.html的代码拆分一下」「做到功能拆分合理，未来可以方便添加功能」）

**结果**：`ui/index.html` 20,344 → 1,479 行，只剩结构；样式进 `ui/css/app.css`（3,394 行）；页面脚本拆成 `ui/js/app/00..17` 共 18 个文件，一个功能一个文件（字典 / 宿主桥接 / 语言菜单 / 导航溢出 / applyI18n / 布局持久化 / 设置面板 / 悬浮提示 / 功能搜索 / 格式转换 / 差异对比 / JSON 对比 / SQL / 表格 / 图片 / 代码生成 / 查询+转义 / 拖放导入）。

**关键点（以后别再踩）**：
- 原来整份脚本包在一个 `document.addEventListener('DOMContentLoaded', async () => {…})` 里，**函数作用域共享**。拆成多个文件后只能靠**经典脚本的全局词法环境**共享 `const/let/function`：所以去掉包装、把 `<script src>` 放到 `</body>` 前（原来脚本后面还有灯箱 / `#pageImportInput` / `#dropVeil` 三块结构，不能原地执行）。
- 跨文件**没有提升**：A 里顶层直接调 B 里的函数会 ReferenceError。经验：确实有跨段调用，但都在函数体里（冒烟 289 条全绿 + Chrome 无 console 错误）。
- 全仓只有**一处顶层 await**（`01-host.js` 的 `await dbxPlugin.ready`）：包成 `void (async () => {…})()`，并在 await 之前先用宿主给的 theme 落一次色（否则首屏会用默认配色画一帧——原来整份脚本都在 await 后面，所以没这问题）。
- 缩进统一去掉 8 个空格，但要**跳过跨行模板字符串内部**（当时 3 段，其中 2 段是误报），否则字符串内容会变。
- 测试跟着改：`i18n.test.js` 拼 index.html + 全部 `js/app/*.js` 再解字典；`assets.test.js` 的 `cssRule` 改读 `ui/css/*.css`；`ui.smoke.js` 里三处 `querySelectorAll('style')` 改读 `CSS_TEXT`。
- 宿主用正则扫 `<script src>` / `<link rel=stylesheet>` 内联，所以 `ui/css/`、`ui/js/app/` 必须在 `ui/` 下、相对路径、<8MB（`assets.test.js` 已守着，资源数 72）。

## 功能搜索改成「顶栏内」+ 回车/输入法修复（0.1.9 收尾）

用户报三连：①顶部布局下搜索浮层压在工具栏上，「从 / 转为」点不到；②输入后按回车，浮层消失但页面没跳；③点语言按钮搜索框就没了。另要求考虑 Windows / macOS 差异。

- **删掉浮层方案**（`.nav-search-wrap.is-float` 整块移除）：顶部布局下按快捷键/点放大镜时给 `body.nav-searching`，CSS 里 `body:not(.nav-left).nav-searching .nav-side, #navMore { display:none }` 把导航那一行让给搜索框；左列布局搜索框本来就常驻顶栏。**任何东西都不再浮在页面或工具栏上**。
- **选中的执行方式**：`navSearchPick` 不再 `el.click()`（宿主 WebView 里合成点击不一定被 `.topbar` 上那条事件委托收到 → 收起了但没跳页），改成直接 `handleNavClick(el)` + `closeNavMore()` / `closeNavConvert()`；`typeof handleNavClick === 'function'` 兜底。**冒烟里的桩要打在 `win.handleNavClick` 上，打死 `el.click` 会失效**。
- **输入法**：`keydown` 里 `if (e.isComposing || e.keyCode === 229) return;` —— 拼音上屏那一下回车/方向键是候选词窗的，抢走就是「想选字结果框没了」。
- **点顶栏按钮不算「点别处」**：document 的 outside-click 里先看 `e.target` 在不在 `.topbar` 内，是就放过（边搜边切语言不丢输入）；切语言后 `applyI18n` 末尾重算结果，避免中英混排。
- **`layoutNav()` 在 `nav-searching` 时直接 return**：导航被 `display:none` 时每项宽度都是 0，不短路会把 11 项全搬进「更多」。
- **平台差异**：`NAV_IS_MAC` 用 `userAgentData.platform || platform || userAgent`；提示文案 `⌘K` / `Ctrl+K`，`aria-keyshortcuts` 写 `Meta+K` / `Control+K`，placeholder 尾巴也标一个。加在 `navSyncSearchLabel()`，由 `applyI18n()` 末尾调用（必须在 placeholder 那一轮之后）。
- 新增 `#navSearchBtn`（放大镜，`data-tip` 空属性 → 取 aria-label）。
- 测试：冒烟 289 → 295（+6 条：按钮/快捷键唤起、回车真跳页、IME 回车不抢、点语言不清搜索、Esc 一下收干净）。
- **Chrome 自动化被权限规则拦**（Chrome 退出时会删自己的临时目录，请求被拒）：不要再重试 CDP/screenshot 那套；改用 `node --max-old-space-size=600 tests/ui.smoke.js`（本机内存吃紧时 jsdom 会被 OOM 杀掉，限堆 600MB 能跑完）。
